01About
About the project

What is PARADA?

PARADA is a mobile and web-based smart parking management system designed to help drivers and parking administrators understand, manage, and monitor parking availability through a unified platform.

Instead of attempting to individually monitor every parking space, PARADA uses zone-based occupancy as its primary operational metric — the zone, not the individual slot, is the authoritative unit of availability.

02Problem
The problem

Parking should be easier to understand.

For drivers

Uncertainty about where capacity is available.

For administrators

Difficulty monitoring occupancy and parking activity manually.

Disconnected parking operations and limited visibility into utilization.

PARADA brings these activities together through one connected system.

03Objective
Project objective

Our goal

To develop a smart parking management system that combines computer vision, license-plate recognition, zone-based occupancy monitoring, parking operations, mobile navigation, and web-based administration into a unified platform.

04How it works
How PARADA works

From arrival to receipt, one pipeline.

01
Vehicle arrives

The vehicle reaches a zone gate or entry point.

02
Zone-gate camera

The gate camera observes the vehicle and captures the license plate.

03
Computer vision + OCR

Image processing reads the plate text.

04
PARADA API

The API determines the vehicle, user, zone, reservation, and admission policy.

05
Vehicle / user / guest resolution

The plate resolves to a registered vehicle and user, or a guest candidate under policy.

06
Occupancy + session

Zone occupancy and the parking session update in the same transaction.

07
Mobile + admin

Both clients read the same backend-authoritative state — drivers on mobile, administrators on the web dashboard.

08
Vehicle exits

The exit camera/OCR event enters the API.

09
Session closes

Duration is computed, the fee is finalized, and the zone's occupancy is reconciled.

07Guest logic
Registered vehicle vs. guest

Guest admission is a policy decision, not a default.

Registered vehicle

Camera + OCR → plate resolves to a registered user → a parking session opens immediately.

Guest vehicle

Plate is unknown → treated as a guest candidate → admission depends on establishment-defined policy.

Policy result

Each candidate is either admitted or denied based on configured guest rules rather than automatic authorization.

Guest admission is controlled by establishment-defined policies rather than treating every unidentified vehicle as automatically authorized.

11Architecture
System architecture

The same journey, seen technically.

Section 04 showed what happens to a vehicle. This is how the system makes it happen: a camera event travels through vision/OCR into the API, which resolves identity, occupancy and sessions, persists them, and propagates the new state to both clients.

Zone Gate Camera

Entry / exit vehicle events.

Computer Vision / OCR

Python · FastAPI · OpenCV · EasyOCR.

PARADA API

Node.js · Express · TypeScript.

Resolution

Registered or guest candidate.

Occupancy & sessions

Capacity − occupied · lifecycle, duration, fee.

Persist + serve

PostgreSQL via Prisma → mobile and admin clients.

Vision reads → API decides → DB persists → clients read

19Transparency
Research / technical transparency

What PARADA currently demonstrates

PARADA demonstrates the integration of mobile development, web administration, backend services, database management, computer vision, OCR, GPS navigation, and configurable parking operations within a single system architecture.

The system is developed as a capstone prototype and evaluated based on functionality, integration, correctness, and system behavior. Formal accuracy evaluation and production deployment are treated separately from the functional implementation.
